# Deploying LEVELED — Render (app) + Neon (Postgres), both free

The backend is a single Express service that also serves the playable web game
at `/`. It self-migrates (`prisma migrate deploy`) and self-seeds (exercises,
gear, challenges, Daily Warrior book, starter programs, starter player) on
boot, so a brand-new database becomes a fully playable game with zero manual
steps.

Hosting layout:

| Piece | Where | Why |
|---|---|---|
| App (API + web game) | [Render](https://render.com) free web service | Auto-deploys from GitHub, 750 free instance-hrs/mo, no card. Spins down after 15 idle min (first visit after that takes ~30–60s to wake). |
| Postgres | [Neon](https://neon.tech) free tier | Permanent free Postgres (0.5GB, scale-to-zero). Render's own free Postgres self-deletes after 30 days — don't use it. |

## One-time setup (~5–10 minutes, works from a phone)

### 1. Create the database (Neon)
1. Go to **neon.tech** → Sign up (Sign in with GitHub).
2. Create a project (name it `leveled`, any region near you).
3. On the project dashboard, copy the **connection string**
   (`postgresql://…neon.tech/neondb?sslmode=require`). That's your
   `DATABASE_URL`.

### 2. Create the app (Render)
1. Go to **render.com** → Sign up (Sign in with GitHub).
2. **New +** → **Blueprint** → select the `justinpz/leveled` repo.
3. Render reads `render.yaml` from the repo root and pre-configures
   everything. When prompted for **DATABASE_URL**, paste the Neon string.
4. **Apply**. The first deploy installs, migrates, boots, and auto-seeds.
   When it goes green, the game is live at the service URL
   (e.g. `https://leveled.onrender.com`).

After that, every push to `main` auto-deploys. Nothing else to maintain.

## Environment variables

| Var | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | The Neon connection string (set during blueprint setup). |
| `NODE_ENV` | yes | `production` (set by render.yaml). |
| `SESSION_SECRET` | yes | Auto-generated by render.yaml. |
| `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` | no | Set both to upgrade program forging from the built-in rule-based generator to a full AI coach. |
| `CORS_ORIGIN` | no | Defaults `*`; the web game is same-origin so this rarely matters. |
| `AUTO_SEED` | no | `false` disables auto-seeding (on by default). |
| `ADMIN_SEED_KEY` | no | Enables `POST /admin/seed` with `x-admin-key` header for manual reseeds. |

## Health & smoke checks

- `GET /health` → `{"status":"ok"}` (Render's health check path).
- `GET /game/shop` → 124 gear items; `GET /programs` → 10 starter programs;
  `GET /challenges/warrior` → today's Daily Warrior session. All seeded
  automatically on first boot.
- `/` serves the web game (the client uses same-origin API calls, so the
  bundle works unchanged on any host).

## Refreshing the web build after app changes

```
cd mobile && npm run export:web && rm -rf ../backend/public && cp -r dist ../backend/public
```

No API URL needs to be baked in — the web client defaults to same-origin.

## Moving hosts later

Everything is in git + one env var. On any Node host: set `DATABASE_URL`,
run `npm install && npm run deploy:start` from `backend/`, done. To go
always-on (no cold starts): Render Starter ($7/mo) or Railway Hobby ($5/mo).
